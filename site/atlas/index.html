Local-first execution

The side panel never holds the engine. It talks over BroadcastChannel to a dedicated worker in the offscreen document. That worker loads spindle_embed_bg.wasm, keeps sessions in OPFS, and continues running turns while the panel is closed.

Trust boundaries

Reading and acting on pages are separate switches, both off until you turn them on. Page tools are accepted only from engine.html; actions use chrome.debugger. Under Before acting (Auto by default in current source, or Ask), an action you allow is done only while the tab still shows the page, part or dialog the question showed you (new in 0.1.7). Provider keys, host tokens, and site secrets are sealed by AES-GCM in the vault.

Preview containment

preview.html is a manifest-sandboxed page with no extension APIs. The service worker serves it under the sandbox CSP and a Connection-Allowlist, which Chrome 152+ enforces for the page and every frame and worker it makes. On older Chrome a preview shows without its scripts, frames or outside links until you run it, and then runs uncontained.

Remote host is optional

A browser can connect to a running Spindle host through the PKCE /connect flow, obtaining a browser token for /v1. Local threads can move to the host; embedded threads use the browser's WASM host.

Preview caveat

Service-worker CSP and Connection-Allowlist contain previews where Chrome enforces the list (152+). Older Chrome shows a preview without its scripts until you run it.

Vault model

Device keys are non-extractable IndexedDB keys; passphrase vaults wrap the key with AES-KW and PBKDF2-SHA-256 at 600,000 rounds. Provider, site, and host records are AES-GCM sealed.

The schema-20 pipeline

The host has a shared turn driver and embedded host, reads helpers, protocol/meta/spend modules, connect and thread services, browser PKCE onboarding, and the browser extension's WASM host. The store still owns the atomic admission → revision → intent → attempt → receipt chain.

Boundary checks

The browser extension is not spindle serve; the PWA is not the extension; spindle-reference is not a runtime; dext app is not a spindle-store dependency.

The four below describe Spindle for Browser 0.1.7. What 0.1.7 added to them: approvals held to the page, slot names a crash cannot split, imports checked from disk, a thread too large to bring back left on the host, and background tasks spared by a parent's Stop.

Approvals held to the page

Before acting is Full (the default), Auto (asks before what sends or submits) or Ask (before every action). An action you allow carries what the question showed: the tab, the page's document (where Chrome says which it is; else its address), the part's description, or the dialog. The service worker checks it just before acting; if the page reloaded or moved on, nothing is done and the thread is told.

Names a crash cannot split

Each slot header this version writes carries a CRC-32 right after its path (in the first 512-byte sector, for paths under about 470 bytes), and every rename writes a record of itself first. A crash at any byte or sector of a header write reopens with each file whole under one of its two names and a directory never split: tested by cutting every byte and every set of sectors in a model of the storage, not a physical power-loss proof.

One live copy

A thread moves between browser and host by bundle and lives in one place: sealed where it left, staged where it arrives. A host unpacks an import into a private staging directory and checks every store there, one import at a time, holding no store in memory; it says a thread's size first, and the browser leaves one over 1 GB on the host. Browser tokens see only their own threads.

Unknown stays unknown

A step cut off is recorded as stopped or unknown, never sent again on its own (unless the session opted in, resend_unknown): Retry sends it once, Take back returns its message. A page action interrupted mid-way is reported unknown. In a thread run in the browser, a parent's Stop leaves its background tasks running, their page actions too.
