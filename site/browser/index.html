01 — WHAT IT DOES

A whole agent, carried into the browser.

Not a chat box that talks to someone's server: the Spindle engine itself, compiled to WebAssembly and running in your browser, with a Linux beside it.

Background

Keeps going with the panel closed.

Threads run in an offscreen worker, not in the panel. Close it, switch tabs, and come back to the answer.

Linux

A real shell, inside the browser.

bash, coreutils, Python 3 with pip, Node with npm, git, curl, jq and ripgrep in Alpine Linux. Each command runs in namespaces of its own, over a copy of the thread's workspace.

Tabs

Reads and works your pages.

With page reading on: list, read and outline tabs. With page actions on: click, type, select, scroll, navigate, answer dialogs and record a tab's network.

Code mode

Scripts that call the agent.

From a command, spindle model, spindle tool and spindle http; from Python import spindle; from Node require('spindle'). Every call is journaled like any other step.

Files

Files in, files out.

Drop files on the panel or picture a tab. Get files back as cards, HTML as a sandboxed preview that runs no script and reaches no site until you allow it, and everything as one .zip.

Keys

Sealed, never sent elsewhere.

Keys and sign-ins are sealed with AES-GCM in the extension's storage, under an optional passphrase, and go only to the provider they were saved for. Or sign in with ChatGPT.

02 — DURABLE, BECAUSE IT IS SPINDLE

Interrupt it. It keeps its word.

A browser is a hard place for long work: tabs close, workers rest, the browser quits. Every thread here is a Spindle session, so each step is committed before the next begins.

  1. The browser closes mid-turn.

    When it starts again, the thread is there, marked interrupted, with every committed step kept. Continue takes it on from there.

  2. Nothing is sent twice by itself.

    A model request whose fate is unknown is shown as unknown. Continue never resends it; Retry sends it once more, on your word.

  3. Go back to before a message.

    The conversation and the workspace's files return together, so nothing from the undone future is left behind.

  4. Take a thread with you.

    Move it to a .spindle file and go on with native Spindle on your machine, in its sandbox with its full tools. Then bring it back.

03 — USE IT FOR

Work that starts on a web page.

Pull data out of pages.

Read several tabs, gather what they say into a CSV, and chart it with Python, without copying a cell by hand.

Do the clicking for you.

Fill in a long form or walk a settings page, one action at a time, on the page you are looking at.

Build a small app and see it.

Write HTML and JavaScript, open it in a preview, change it, and download the folder when it works.

Make sense of a file.

Drop in a log, a spreadsheet export or a JSON dump and ask what is in it. Python does the counting; you get the answer and the script.

See what a page loads.

Record a tab's requests and read the responses, to find the call behind a broken button.

Research across tabs.

Compare what several pages say and keep a written summary in the workspace, with where each claim came from.

05 — STAY IN CONTROL

It acts when you say, where you can see.

Off until you turn it on

Your tabs are yours.

A new install reads no page and acts on none. Page actions need page reading, and both need the browser's site access, which you can take back in one click.

Visible

The browser shows when it acts.

The browser's debugging bar is up while Spindle acts on a tab. Close the bar and Spindle leaves that tab alone until you turn page actions off and on.

Precise

Clicks land where they aim.

If something covers the target, such as a banner or a dialog, nothing is clicked or typed, and the agent is told what is in the way. Two threads never type into one tab at once.

Never by itself

No repeat clicks.

Spindle never repeats a click, a keystroke or a navigation on its own after an interruption. Reading tools may rerun; acting tools never do.

Contained

Commands stay in their Linux.

Network for commands is off for each thread until you turn it on. Through the browser, it reaches public sites only: local and private addresses are refused, and requests carry no cookies.

Sealed

Keys never sit as text.

Every key is sealed. Set a passphrase, and what is sealed from then on is useless in a copy of your browser profile without it.

What it cannot promise.
  • A page can carry text written to steer an agent. Turn on page reading for sites you trust, and read what the agent proposes before it acts on anything that matters.
  • A click, a submitted form or a sent request cannot be taken back. Spindle tells you when one may have happened; it cannot undo it.
  • Through the browser, local addresses are refused by name and number, but the browser resolves names, so a public name that points into your own network is not caught. A relay you set up reaches whatever it can reach.
  • Without a passphrase, the key that seals your keys lives in the same browser profile.

06 — YOUR MODEL

Bring the model you already pay for.

Requests go from your browser straight to the provider. No Spindle server sits in between.

  • DeepSeek key
  • ZAI GLM key
  • Kimi Code key
  • OpenAI API key
  • Anthropic key
  • ChatGPT sign in
  • Local llama.cpp no key
  • Your own providers.json

Sign in with ChatGPT uses your ChatGPT plan. Anthropic models take an API key; a Claude subscription sign-in is not offered. Any OpenAI-compatible endpoint can be added with a providers.json.

07 — INSTALL

Download, load, sign in.

Spindle for Browser is not in the Chrome Web Store or Edge Add-ons yet. Each release is a zip built and checked by the repository's own workflow; you load it as an unpacked extension.

  1. Download the zip.

    Use the Download button, or take spindle-browser-VERSION.zip from the latest release, and unzip it into a folder you will keep. To check it, use the .sha256 file beside it on the release, or gh attestation verify with the zip and -R SiliconState/Spindle.

  2. Load it.

    Open chrome://extensions (in Edge, edge://extensions), turn on Developer mode, click Load unpacked and choose the folder. Pin Spindle to the toolbar.

  3. Open the panel and connect a model.

    Click the toolbar button, open Settings, and add a key or Sign in. The browser asks for access to that provider's site.

  4. Update in place.

    Unzip the next version over the same folder and click Reload on Spindle's card. The browser names an unpacked extension by its folder, and its threads and keys live under that name, so another folder is a separate install.

Or build it yourself

On Linux, or in WSL on Windows (copy chrome/dist to a Windows folder to load it). It needs Rust, clang, curl, npm, python3 and user namespaces; Ubuntu 23.10 and later allow them only after sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0.

rustup target add wasm32-unknown-unknown i686-unknown-linux-musl
cargo install wasm-bindgen-cli --version 0.2.129 --locked
git clone https://github.com/SiliconState/Spindle.git
cd Spindle/spindle
chrome/linux/build.sh   # the browser Linux, into chrome/linux/dist
chrome/build.sh         # the extension, into chrome/dist

For the faster wasm Linux (below), build it and pass SPINDLE_WASM_LINUX (how). How it is built.

08 — SPEED

Faster still, built from source.

Release zips carry the v86 Linux, an emulated PC. Built from source with its optional wasm Linux, the extension runs the commands it can there, at the machine's own speed with no emulator in between: plain sh commands run 2.2 to 8.6 times faster, and Python up to 26 times. What the wasm Linux cannot run (bash itself, Node, git, the network) stays on the v86 Linux.

09 — QUESTIONS

Asked before installing.

Which browsers does it work in?

Chrome and Edge, version 116 or later, on desktop; both are tested. It is a Manifest V3 extension with a side panel. Other Chromium browsers are untested.

Do I need Spindle on my computer too?

No. Connecting a native Spindle host is optional, and only adds a second place for commands to run.

Where do my keys go?

They are sealed in the extension's IndexedDB and opened only by its engine, for a request to the provider they were saved for. If a provider list later points that provider at another address, the request is refused. Exported threads carry no keys.

Can it see my other tabs?

Only with page reading on, which a new install has off. Page actions are a second switch on top of that. Take the browser's site access back and both go off.

What happens if the browser closes in the middle of a turn?

When it starts again, the thread says it was interrupted, with every committed step kept. Continue goes on and never resends a request whose fate is unknown; Retry sends it once more if you choose.

What does it cost?

Spindle is free (MIT). Your provider bills model use to your key or plan. Threads in the browser have no spending limit of their own; native Spindle has --max-usd.

Can I use my ChatGPT or Claude subscription?

ChatGPT, yes: Sign in in Settings. Claude, through an Anthropic API key; signing in with a Claude subscription is not offered.

Where are my threads kept?

In the extension's own storage on this computer. Removing the extension removes them; move a thread to a .spindle file first to keep it.
