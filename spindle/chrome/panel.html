Providers

Keys and sign-ins stay in this browser, encrypted in Spindle's own storage, and go only to their provider. Saving one lets Spindle reach that provider's site.

Provider list

Pages
Page readingThreads list your tabs, read the page you are on (or one they name), and see its parts and HTML.
Page actionsThreads also go to addresses, click, type, choose, press keys, scroll, wait, picture pages, close tabs and watch a tab's network.

Acting, a thread works in your browser signed in as you, so a page's text can steer it. Chrome shows that Spindle is debugging a tab while it acts on it; closing that bar stops it there.

Commands

Threads run bash in a Linux inside this browser (bash, Python, Node, git, curl), sealed off from your computer and from Spindle's keys. It starts with the first command. A thread's commands reach the web only once you turn its network on (the thread's model menu).

Network
Relay

Without one, a thread with network reaches websites through Chrome (HTTP and HTTPS; no cookies). With a relay you run (a WISP server, such as wisp-js or epoxy-server), its commands reach any address through it: ssh, git over SSH, databases. Names are then looked up over DNS-over-HTTPS (cloudflare-dns.com). Spindle runs no relay of its own.

Sites scripts may call

A script can call a site you list here with spindle http URL, whatever its thread's network: journaled like every Spindle call, sent without your cookies. Chrome asks once for each.
